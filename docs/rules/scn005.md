# SCN005: `SELECT *` reads every column of a large table

A query reads a table with `SELECT *`, and every column reaches the result, so BigQuery bills every column in every partition the query touches. On an unclustered table `LIMIT` doesn't help: BigQuery bills what it reads, not what it returns.

| Bytes `SELECT *` reads from the table | Severity |
| --- | --- |
| 1 GiB or more, or unknown | **warn** |
| Less than 1 GiB | no finding: reading every column costs little |

The bytes come from the [cost estimate](../estimate.md) for every `SELECT *` read of that table together, after their partition filters: two `UNION ALL` branches over different days add up. The message gives them when the estimate knows which partitions the filters keep. Without a partition list, it can't tell how much a date filter keeps, so the message leaves the amount out, as it does when BigQuery would reject the query.

## Evidence

Billed bytes for one partition of Google Trends' `top_terms`, measured on 2026-10-01 ([#16](https://github.com/tjslezak/Scanisaur/issues/16)):

| Query | Billed |
| --- | --- |
| `SELECT * … WHERE refresh_date = '2026-09-30' LIMIT 10` | 99.6 MB |
| The same without `LIMIT` | 98.6 MB (dry run) |
| `SELECT term, rank` from that partition | 46.8 MB (dry run) |

## When it applies

- `SELECT *`, `SELECT t.*` or `SELECT * EXCEPT (…)` on the table, whether in the outer query, a CTE or a subquery, as long as the columns it selects reach the result. With `EXCEPT`, the message says how many of the table's columns are still read.
- With an outer `LIMIT` and no aggregation, the message says `LIMIT` doesn't reduce the bytes billed. Agents often preview a table this way. On a clustered table, `LIMIT` can stop the scan early, so the message makes no such claim and gives the amount as an upper bound.

## When it stays silent

- **Fewer columns used:** a `SELECT *` in a CTE or subquery whose reader picks a few columns, as in `WITH t AS (SELECT * FROM events) SELECT user_id FROM t`, and `EXISTS (SELECT * …)`, which reads only the columns its conditions use. BigQuery reads only the columns the query uses. An `EXCEPT` written above a CTE's `SELECT *` isn't followed, so that read isn't reported either.
- **`LIMIT 0`,** which returns only the schema, and **`TABLESAMPLE`,** which reads a sample of blocks.
- **Nothing read:** `COUNT(*)` over a `SELECT *`.
- **Small reads:** tables, or the partitions a query keeps, under 1 GiB.
- **Views and external tables:** a view's columns come from tables the query doesn't name, and an external table bills its files whatever columns are read.

## Fix

Select only the columns you need. For column names and types, use `scanisaur_schema_describe`, which reads no data.
