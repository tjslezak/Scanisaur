# SCN009: a result with every row of a large table

A query returns every row it reads of a table, with no `LIMIT`, aggregate or filter beyond whole partitions, and that is at least 10,000 rows. Nobody reads that many rows, and an agent that asked for them fills its context with rows instead of the answer. BigQuery doesn't stop it: bytes billed are the same with or without the rows coming back.

| Rows the result holds | Severity |
| --- | --- |
| At least 10,000, counted exactly | **warn** |
| Fewer, or a count that isn't known | not reported |

The threshold is a policy setting (`unbounded_result_rows`). The rows are the table's row count times the share of its bytes in the partitions the query's filters keep, as in the [cost estimate](../estimate.md). Two `UNION ALL` branches add up.

## When it applies

The rows of a table reach the result when nothing between the table and the outer query can drop or merge them:

- the table is read in `FROM`, directly or through CTEs and subqueries, which may filter it only on its partition column or `_TABLE_SUFFIX`, keeping whole partitions;
- every join is a `LEFT JOIN` (or `FULL JOIN`), which keeps each row of the table;
- every `UNION` is `UNION ALL`;
- no SELECT on the way has a `LIMIT`, `GROUP BY`, aggregate, `DISTINCT`, `HAVING` or `QUALIFY`.

`ORDER BY`, window functions and scalar subqueries in the `SELECT` list don't change the number of rows, so they don't stop the rule.

## When it stays silent

- **`LIMIT`, of any size:** a limit is a choice of how many rows to see.
- **An aggregate, `GROUP BY` or `DISTINCT`,** in the outer query or a CTE it reads.
- **A filter that isn't on whole partitions,** as `term = 'x'`, `DATE_DIFF(day, DATE(ts), DAY) = 0`, or `EXISTS` and `IN (SELECT …)`: it may leave a handful of rows.
- **An inner or comma join, or `UNNEST`:** the join may drop rows, or repeat them; how many isn't known without keys.
- **`UNION DISTINCT`, `INTERSECT` and `EXCEPT`.**
- **Unknown counts:** a table without a row count, a view, or a partition filter on a table whose catalog lists no partitions.
- **Small results:** under the threshold, as a 365-day calendar.
- **`TABLESAMPLE`,** **`LIMIT 0`,** and **writes** such as `CREATE TABLE … AS SELECT` or `INSERT … SELECT`, whose rows go to a table, not back to the agent.
- **A query BigQuery would reject,** because a table requires a partition filter it doesn't have ([SCN003](scn003.md)).

## Fix

Aggregate to get the answer instead of the rows, with `COUNT`, `SUM` or `GROUP BY`, or add a `LIMIT` to look at a sample.
